# OAR v0.1.0 release plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to execute this plan.

**Goal:** Publish a clear, accurately presented, licensed and citable OAR research release.

**Architecture:** Preserve the reviewed implementation and immutable scientific records. Add publication metadata, shorten the human README and keep detailed reproduction instructions separately. Refresh current evidence bindings, review, then publish the existing Git history and a checksum-verified offline bundle.

**Tech stack:** Existing Python/PyTorch project, setuptools, Git and GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-10-31-release-design.md`.

## Global constraints

- Work on current `main` and make meaningful commits. No new research, dependencies, trainer, controller or claim of training speedup.
- Preserve original science/configuration bytes, source attribution and scientific gate prefix.
- Use the owner's verified AGPL-3.0-only/CC-BY-4.0 split for original material only. Preserve upstream rights and notices.
- Use write-like-me only for README reader-facing prose. Be concise and specific.
- Publish to `arlegotin/optimizer-aware-residual-auditing`, tag `v0.1.0`; no force push or package-index publication.

## Review focus

Check that the README cannot turn component timings into a training claim; original licenses do not cover third-party material; CFF and package metadata agree; historical artifact lookup survives a clean full clone; and release assets exclude ignored data, checkpoints and credentials.

- [ ] Update package metadata and write release notes. Preserve measurement qualifications and AI/write-like-me attribution.

- [ ] Build and inspect the package; prepare an offline Git bundle and checksums from the verified release commit/tag.

## Task 3: Publish and verify

- [ ] Push reviewed `main` and annotated `v0.1.0` through authenticated Git without rewriting history.
- [ ] Make the repository public, set its accurate description/topics and create the GitHub release with notes and verified assets.
