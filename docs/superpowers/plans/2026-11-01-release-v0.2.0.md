# OAR v0.2.0 release plan

> Execute autonomously within the owner's explicit publish request; use a fresh
> independent release reviewer before publication.

**Goal:** publish the completed study as a useful, clearly explained research release.
**Spec:** decisions/releases/v0.2.0-publication.md and the matching release design.

1. Inspect current account conventions, requested writing skill and remote refs;
   preserve the study in an isolated release worktree. Completed before edits.
2. Rewrite human README, update citation/package/reproduction/upstream notices,
   add a short public-metadata verifier and versioned legacy index. Keep raw
   scientific artifacts and license texts unchanged.
3. Bind current edited documents and release index in a new prospective amendment;
   retain all old authorizations as archived history. No new learning authority.
4. Run package/metadata/link/public-replay/legacy-report checks and applicable
   suite; build and inspect the distribution. Review the actual release diff.
5. Preserve local checks and independent review; commit release sources, tag
   v0.2.0, create a complete-history bundle and checksums, and verify assets.
6. Fast-forward remote main and publish the release; verify remote commit/tag,
   release visibility and downloadable assets. Keep research history intact.

No corpus/checkpoint assets, new algorithms, outcome retuning, performance
remeasurement, force push, or package-index publication are in scope.
